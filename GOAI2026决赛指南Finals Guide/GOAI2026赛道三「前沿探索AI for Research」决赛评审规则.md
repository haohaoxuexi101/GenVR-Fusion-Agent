# GOAI2026赛道三「前沿探索AI for Research」决赛评审规则

**GOAI 2026 赛道三「前沿探索 AI for Research」**

**决赛评审规则**

适用阶段：GOAI 2026 决赛

|规则定位：本规则用于统一赛道三决赛两个独立评审单元（算法赛题、开放探索赛题）的项目展示、评委评分、客观成绩合成、技术及事实核验、成绩计算、异常复核、结果确认与程序性申诉。|
|---|

# **一、适用范围**

本规则适用于 GOAI 2026 世界人工智能开源大赛赛道三「前沿探索 AI for Research」决赛阶段。赛道三分为“算法赛题”和“开放探索赛题”两个独立评审单元，分别评分、分别排名。

初赛、复赛成绩仅作为相应阶段的晋级依据，不计入决赛成绩。决赛依据最终封版材料、现场展示、答辩、客观评测（算法赛题）及其他可核验证据独立计分并确定最终排名。

# **二、评审原则**

**1\. 公平一致：**所有决赛项目采用统一的评分维度、分值结构、评分标准、计分方式及结果确认流程。评审不得因参赛团队所属高校、企业、机构知名度、融资情况、商业资源、既往奖项等与本次赛事评价无直接关系的因素改变评价标准。

**2\. 独立评审：**正式评委应依据项目封版材料、代码及工程材料、现场 PPT、Demo、运行记录及现场答辩等独立完成评分。评分正式提交前，评委之间不得交换具体分数、项目排名或投票倾向。评委合议不得替代个人独立评分，不得要求评委为形成统一意见而修改评分。

**3\. 证据导向：**项目价值、创新能力、技术实现、运行效果及开源成果等评价，应以可核验事实和项目实际表现为主要依据。仅有概念描述、未来规划或无法核实的口头陈述，不按照已经实现的能力计分。

**4\. 成果一致：**参赛团队现场展示的 PPT、Demo、代码、运行结果和答辩陈述应保持基本一致。如现场陈述与最终封版材料、代码或实际运行结果存在明显矛盾，应优先开展事实核验，并依据可验证材料进行判断。

**5\. 规则冻结：**决赛开始前，应完成评分维度、分值、二级考核点、成绩计算方式、异常复核机制及同分处理规则的确认和冻结。规则冻结后，不得临时增加、删除或调整影响项目得分及最终排名的实质性评价标准。

**6\. 全过程留痕：**评委评分、利益冲突回避、技术核验、异常复核、成绩调整、同分处理、结果确认和程序性申诉等关键环节应形成必要记录。

# **三、决赛评审方式**

赛道三决赛采用“最终封版材料 \+ 现场展示/研究证据说明**（ppt\+demo演示）** \+ 评委提问答辩 \+ 技术及事实核验”的方式进行；其中算法赛题另叠加赛前封版的官方客观技术成绩。现场展示和答辩用于核验研究主张、方法边界、实验结果和证据，不单独设置表达分。

## **1\. 现场展示**

参赛团队应结合所属评审单元，清晰呈现研究问题、方法与技术路线、实验或探索过程、关键结果、局限与边界以及开放复用情况。重点可包括：

1. 研究问题、任务目标及科学意义

2. 相关工作、基线或现有研究范式

3. 方法、模型、环境或 Agent/探索机制设计

4. 实验、搜索、对照或消融设计

5. 关键结果、失败结果及其解释

6. 代码、环境、数据处理流程与第三方依赖边界

7. 开放材料、复现路径及后续研究价值

## **2\. ****实验 / 系统 / 研究证据说明**

参赛团队可根据项目形态，通过实验结果、代码与环境、日志、探索轨迹、运行记录、系统演示或其他可核验证据说明核心能力。评委可重点核验：

1. 关键实验或研究结果是否与封版材料一致

2. 基线、对照、消融、统计或复验条件是否充分

3. 方法、模型、环境、工具或科研 Agent 的核心机制是否真实存在

4. 实验记录、搜索空间、探索轨迹、日志或产物是否可检查

5. 结果边界、失败模式及限制条件是否被如实说明

6. 第三方模型、数据、商业 API、闭源组件和 License 是否完整披露

## **3\. 现场答辩**

评委可围绕以下内容提问，团队应配合完成与评分相关的关键事实核验：

1. 问题定义、科学意义与研究边界

2. 方法/模型/研究路线及相对相关工作的实质差异

3. 实验设计、基线比较、对照/消融与结果解释

4. 研究过程、代码/环境、日志及证据链

5. 结果可复验性、失败结果、限制条件与能力边界

6. 开放范围、复现路径及第三方接续价值

# **六****、技术及事实核验**

|定义：技术及事实核验，是指评委针对可能影响评分的关键技术能力、研究结果及客观事实，通过最终封版材料、代码/环境、实验记录、日志、探索轨迹、运行结果、方向量化指标/客观评测记录（如适用）及现场答辩等方式进行验证，以确认相关研究主张是否真实、相关结论是否有证据支撑、材料之间是否一致。技术及事实核验不单独计分，其结果作为各评分维度判断的重要依据。|
|---|

**正式评分依据以下材料：**

1. 项目最终封版提交材料

2. 代码仓库、模型、环境及可验证工程/研究材料

3. 赛前封版客观评测及跨方向校准结果（算法赛题有技术分方向）

4. 实验结果、对照、消融、统计或基线数据

5. 日志、探索轨迹、运行记录或实验产物

6. 现场展示与答辩

7. 组委会允许使用的其他验证材料

**技术及事实核验可重点确认：**

1. 方法、模型、环境、科研 Agent 或探索机制是否真实存在并与封版材料一致

2. 关键实验、基线、对照、消融、统计分析或研究信号是否具有可核验证据

3. 代码/环境、日志、探索轨迹、实验产物与现场陈述是否相互一致

4. 结果、结论、失败模式、限制条件和能力边界是否如实披露

5. 第三方数据、模型、商业 API、闭源组件及 License 是否完整披露

6. 是否存在伪造结果、套壳、抄袭、未披露已有项目基础或虚构团队贡献等真实性问题

当不同证据之间出现明显冲突时，应优先核验可重复、可检查的客观记录和工程/研究材料。资格、原创性与真实贡献、作品真实性、代码/复现要求以及数据和第三方依赖合规，与项目主观评分相互独立；确认存在严重违规时，可依据赛事规则取消成绩或获奖资格，不以主观扣分替代资格处理。

# **七****、评委组成与利益冲突回避**

赛道三算法赛题与开放探索赛题原则上各配置 5 名正式评委，并根据入围项目方向覆盖 AI 方法及相关科学领域。因临时缺席或利益冲突回避造成有效评分减少时，单个项目不得少于 3 名有效评委；少于 3 名时应补充评审。

**存在以下关系之一的评委，应主动申报并回避相关项目评审：**

1. 与项目团队存在任职关系

2. 与项目或团队存在投资关系

3. 存在导师/学生等直接关系

4. 参与项目直接合作研发

5. 近期存在重大商业合作

6. 存在其他足以影响独立判断的实质关系

**回避评委不得参与该项目评分，其评分不纳入该项目最终成绩。**

# **八****、评分提交与成绩计算**

**1\. 算法赛题**

每名正式评委按照本规则规定的二级考核点逐项评分，单名评委总分满分 100 分。项目最终成绩按照全部有效正式评委总分的算术平均值计算。算法赛题最终得分 = 有效正式评委总分之和 ÷ 有效评委人数。

**2\. 开放探索赛题**

每名正式评委按照本规则规定的二级考核点逐项评分，单名评委总分满分 100 分。项目最终成绩按照全部有效正式评委总分的算术平均值计算：

开放探索赛题最终得分 = 有效正式评委总分之和 ÷ 有效评委人数

**3\. 计分精度与完整性**

最终成绩原则上保留至小数点后两位。正式提交评分前，评委应确认本人负责的全部考核点均已完成评价，不得无理由漏评。

# **九****、评分锁定与修改**

每支队伍完成展示和答辩后，正式评委应独立提交本人负责的评分。评分提交并锁定后原则上不得修改；评分锁定前不得讨论具体分数、排名或奖项倾向。

仅出现以下情况时，可重新开放相关评委本人评分；如涉及算法赛题量化指标，则由组委会按封版规则更正相应记录：

1. 技术或事实核验发现原评分依据中的客观事实存在错误

2. 使用了错误的作品或材料版本

3. 出现分数录入错误

4. 出现其他明确的程序性错误

重新开放评分须记录修改前后分数、原因和时间。

# **十、评分复核与评委合议**

全部项目评审完成后，由组委会组织评分复核及必要的评委合议。其目的为确认评分完整性、核验影响评分的客观事实并处理程序问题，不用于统一评委专业判断。

**1\. 评分复核内容**

1. 评委评分是否存在漏项

2. 有效评委人数是否符合要求

3. 是否存在应回避未回避情况

4. 是否存在录入或计算错误

5. 是否触发异常分差复核

6. 是否存在尚未确认的重要技术或研究事实

7. 是否正确执行同分处理规则

**2\. 评委合议原则**

评委合议不得：

1. 统一评委分数

2. 人为缩小评分差距

3. 以排名结果倒推评分

4. 要求评委为形成统一意见修改分数

5. 除本规则“同分处理”明确规定的匿名投票外，不得通过集体投票替代正式评委个人独立评分

# **十****一****、异常分差复核**

**同一项目有效评委独立评分部分的最高分与最低分之差达到该评委独立评分部分满分的 20% 时，自动启动事实复核：**

算法赛题：100 分制最高分与最低分相差达到 20 分及以上

开放探索赛题：100 分制最高分与最低分相差达到 20 分及以上

**异常复核仅针对影响评分的客观事实，包括但不限于：**

1. 方法、模型、环境、科研 Agent 或核心研究能力是否真实存在

2. 关键实验、性能或研究结果是否存在有效证据

3. 材料、代码/环境、实验记录与现场陈述是否一致

4. 第三方数据、模型、API 或闭源依赖是否充分披露

5. 代码、实验、日志、探索轨迹或结果是否可验证

6. 是否存在对项目关键技术事实或研究边界的明显误解

事实确认后，正式评委可维持原评分或依据核验事实独立调整本人负责的评分；不得以缩小分差或形成一致意见为目的要求评委修改评分。

# **十****二****、同分处理**

**1\. 算法赛题**

如两个或以上项目最终得分完全相同，依次比较：

1. 问题价值与实际影响

2. 创新性

3. 技术 / 研究深度

4. 完成度与可验证性

5. 开源价值与复用

**2\. 开放探索赛题**

如两个或以上项目最终得分完全相同，依次比较：

1. 问题价值与实际影响

2. 创新性

3. 技术 / 研究深度

4. 完成度与可验证性；

5. 开源价值与复用

按上述顺序仍完全同分的，由未回避的正式评委仅针对并列项目进行一次匿名投票；仍无法形成唯一结果时，由组委会启动补充复核并留档。不得在出现同分后临时新增新的评分指标。

# **十****三****、成绩汇总与结果确认**

全部评分完成后，由指定工作人员统一进行成绩汇总，并进行独立复核。成绩确认实行“一人负责计分或汇总、一人进行独立复核”。

正式结果确认前，应重点核查：

1. 有效评委人数

2. 利益冲突回避情况

3. 评委负责评分的考核点完整性

4. 项目最终成绩计算

5. 分数录入错误

6. 异常分差复核

7. 同分处理

8. 技术及事实核验情况

在最终成绩完成确认前，不得提前公布正式排名。算法赛题与开放探索赛题分别确认、分别排名。

# **十****四****、排名公布与程序性申诉**

排名由组委会完成评分汇总、成绩复核及结果确认后统一公布。程序性申诉用于纠正可核验的事实或流程错误，不用于重新评价评委正常的专业判断。

**参赛团队可针对以下事项提出程序性申诉：**

- 使用了错误的作品或材料版本

- 分数录入或成绩计算错误

- 应回避的评委未执行回避

- 规则执行与公开规则明显不一致

- 客观记录、实验记录或技术事实存在明显错误

**程序性申诉原则上不受理以下事项：**

- 单纯不同意评委专业评价

- 以“本人分数偏低”为由要求重新评分

- 要求更换评委后重新评价

- 仅以其他项目得分为由要求调整自身得分

- 对正常专业判断本身提出重新投票要求

申诉时限、渠道和材料要求按大赛统一申诉规则执行。经核查确认存在确需纠正的程序或事实错误时，组委会应依据已冻结规则进行更正并留档。

# **十****五****、其他特殊情况处理**

**1\. 现场设备或网络异常**

如因赛事现场统一设备、网络或其他组委会可确认的客观因素影响正常展示，现场工作人员可根据实际情况安排合理的技术处理。任何处理不得使单一项目获得明显额外展示或答辩优势。

**2\. 第三方服务或研究环境异常**

如现场展示依赖第三方模型、API、云服务、数据服务或特定研究环境，参赛团队应说明相关依赖边界。现场临时异常时，可结合封版材料、实验记录、日志、代码/环境及其他可验证材料进行事实核验。

**3\. 无法核验的关键研究主张**

对于参赛团队声称已经实现、但现场及封版材料均无法提供合理验证证据的关键能力、实验结果或研究结论，评委可不按照“已实现/已验证成果”给予对应主观评价。

**4\. 封版后新增成果**

决赛评分原则上以最终封版成果为基础。现场展示出现封版后新增且可能实质影响评分的重要结果、功能或实验时，组委会可核验其是否属于允许展示范围；不得通过未经统一确认的新增成果破坏不同项目之间的评审一致性。

**5\. 材料合规性**

封版材料、PPT、代码仓库说明及现场陈述，不得包含侵犯第三方知识产权、商标权或构成不正当竞争的表述。组委会发现的，可要求在决赛开始前整改；拒不整改的，相关表述不作为评分依据。
